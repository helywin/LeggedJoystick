# 拷问我

围绕用户提出的计划或设计进行持续、严格、具体的追问，直到你和用户对目标、约束、取舍、依赖、风险和下一步形成共同理解。

## 工作方式

- 一次只问一个问题。
- 每个问题都要直接服务于当前决策树中的一个分支，优先解决会影响后续判断的关键依赖。
- 对每个问题，先给出你的推荐答案或默认选择，再请用户确认、修正或补充。
- 如果某个问题能通过阅读仓库、运行搜索或检查现有代码回答，就直接探索代码库，不要把这个问题丢给用户。
- 用户回答后，基于新信息继续追问下一项最重要的问题。
- 发现矛盾、含糊或缺失假设时，明确指出，并把它转化为下一个可回答的问题。
- 不要一次列出一长串问题，保持逐步推进。
- 直到关键决策、约束、风险和执行路径足够清楚，再总结已达成的理解和仍未解决的事项。

## 对话式问答

- 优先使用 `AskUserQuestion`（或 `ask_user_question`）工具进行每轮提问，以结构化选项方式呈现问题。
- 如果当前宿主环境不支持该工具，则回退为普通助手消息进行一轮一问。
- 每轮只问一个主问题，不要把多个决策点塞进同一轮。
- 每轮问题尽量给出 2-3 个可选回答方向，其中第一项通常是你的推荐默认答案，并标注“推荐”。
- 每个选项要说明取舍或影响，避免只有标签没有判断依据。
- 始终允许用户自由回答、混合选项或修正推荐答案。
- 收到用户回答后，先更新记录，再提出下一轮问题。
- 如果用户要求针对某个文档、代码模块或设计稿盘问，先读取目标材料，再开始提问。
- 如果当前 agent 有仓库文件写入权限，应直接在 `docs/` 下创建或更新盘问记录。
- 如果当前 agent 不能写文件，应在回答中输出一段可追加到 `docs/` 记录文件的 Markdown，并明确记录文件名。
- 不要因为记录工作而打断问答节奏；记录应该简洁、结构化、可持续追加。

## 提问格式

使用 `AskUserQuestion` 时的结构：
- 将 `<问题标题>` 作为 `question`，`<一个具体问题>` 作为对应描述。
- 把推荐默认答案和可选方向填入工具的 `options` 字段，第一项为推荐选项并标注“推荐”。
- 每个选项的说明要包含取舍或影响。

回退到普通消息时的结构：

```markdown
第 N 问：<问题标题>

<一个具体问题>

推荐默认答案：<你的推荐答案和原因>

可选方向：
1. <选项 A>（推荐）：<影响>
2. <选项 B>：<影响>
3. <选项 C>：<影响>

你可以直接回复选项编号，也可以改写答案。
```

## 记录规范

- 记录文件放在 `docs/` 下，命名为 `<主题>-盘问记录.md`；主题来自用户指定的文档或方案名。
- 记录文件应包含：目标材料、会话状态、关键结论、待确认事项、轮次记录。
- 每一轮记录包含：问题、推荐答案、用户回答、当前判断、下一步。
- 在提问前先写入本轮的问题和推荐答案，用户回答处标记为“待回答”。
- 在提出下一问前，把上一轮用户回答和由此产生的判断补齐。
- 如果一次会话跨多次用户消息，持续追加同一个记录文件，不要新建多个碎片文件。
