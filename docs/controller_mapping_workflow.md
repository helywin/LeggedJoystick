# 机器人主控与实时建图工作流

## 连接边界

App 同时维护两条连接：

- `tcp://<robot-ip>:33445`：`legged_driver`，负责摇杆、动作、速度档和底盘状态；
- `tcp://<robot-ip>:33446`：`sar_robot_controller`，负责业务状态、AppMode/控制权闭环、
  时间同步、建图命令、实时地图和位姿。

两条连接独立重连。主控离线时仍可保留健康的手动遥控链路，但建图按钮全部禁用；此时
只允许直接请求底盘 MANUAL 作为安全降级，不允许直接发送 AUTO。AUTO 只能由主控接受
导航任务后进入，主屏在自动导航状态显示“自动·接管”，点击执行人工接管。

## 建图操作

1. 设置页配置机器人 IP、驱动端口、主控端口和部署令牌。日志不会输出令牌。
2. 连接后 App 完成 Hello、状态订阅、心跳和四时间戳对时；主控 `allowed_actions` 允许后
   才能点击“开始建图”。
3. 建图工作区显示 `MAPPING_RUNNING + REMOTE_MANUAL`，操作者继续通过原摇杆链路低速
   行走，同时查看地图覆盖范围和机器狗位置。
4. “结束建图”进入复核，保留最后完整地图；随后选择保存地图或放弃草稿。
5. 地图停止更新、分片缺失或哈希错误时，App 保留上一完整帧并自动请求最新完整帧。

## 地图坐标语义

App 按 ROS OccupancyGrid 行序解码 `-1..100` 的 int8 数据，显示时翻转纵轴。机器人位姿
只接受 `frame_id=map` 且来源为建图里程计的数据，先减去地图 origin，再应用 origin yaw
逆旋转和 resolution 换算，最后叠加位置圆点和朝向线。地图和位姿年龄会分别显示，旧
数据不会伪装成实时状态。

当前地图与遥控器协议仍处开发阶段，完整的 `origin=[x,y,yaw]` 是唯一有效格式。主控不得把
缺失 yaw 的旧地图包静默解释为零，App 缺少完整元信息时必须禁用选点。开发数据在部署前
直接迁移、清理或重新保存，不为旧格式保留双解析和默认值兼容分支。

## 已保存地图定位与导航

1. App 建立新的主控会话后主动刷新地图列表；操作者选择地图后，App 以单请求方式获取
   PNG 预览并按内容哈希写入私有原子缓存。分片不完整、元信息冲突、哈希错误、图片无法
   解码或请求超时都不会替换上一张有效预览。
2. “加载选中地图”只在主控权威 `allowed_actions` 允许时发送。切图、会话变化、地图
   revision 变化、定位丢失或控制权变化会使旧初始位姿草稿、目标草稿和规划路径失效。
3. 初始位姿和导航目标通过在地图上按下并拖动设置位置与朝向。进入编辑时地图自动全屏，
   拖动期间实时显示 x、y、yaw 和临时朝向箭头；坐标转换使用完整 `origin=[x,y,yaw]`、
   resolution、图片纵轴翻转和 letterbox 偏移。点到地图留白、未知或占用栅格时拒绝生成
   草稿，退出全屏后仍需通过独立按钮确认发送。
4. 规划预览返回的路径必须同时匹配当前会话、地图、目标代次和 request ID。只有定位、
   控制权、健康状态及 `allowed_actions` 仍满足要求时才可开始导航；目标被编辑、主控断连
   或定位失效后，旧路径不能继续使用。
5. 导航中始终保留取消和人工接管入口。人工接管复用既有安全闭环，先请求停止自动任务，
   再由权威 AppMode 回到 MANUAL；App 不在重连后重放旧导航目标。

## 验证边界

- Kotlin 单元测试覆盖协议封装、真实 ROUTER 握手、地图分片/哈希/zlib、超时、重连和
  坐标转换。
- 工程 Mock 提供固定栅格和位姿，只用于布局与交互检查。
- 最终真机验收必须同时打开 RViz，对比 `/map`、`/odom/slam_odom`、AppMode、地图位置和
  朝向；代码测试和 Mock 截图不能替代 NX 与遥控器真机结论。

## G20 工程 Mock 实机验证（2026-08-18）

- 验证设备为 Android 13 G20 遥控器，物理分辨率 1200×1920，App 强制横屏后的有效
  分辨率为 1920×1078。
- 验证期间启用工程 Mock，并确认 App 没有建立到 `192.168.234.1:33445` 或 `:33446`
  的 TCP 连接，因此不会向真实底盘或主控下发命令。
- 建图运行阶段确认实时地图帧、运动中的机器人位置与朝向、运行态、控制权、健康、对时、
  地图与位姿年龄、拒绝与丢弃计数均能在单屏完整显示；连续采样确认地图帧号和位姿发生变化。
- 修复了固定高度状态栏导致位置与朝向被裁切的问题，以及地图帧与界面计时器交错更新时
  偶发“时钟异常”的问题。年龄计算现使用本地单调时钟，并有纯 Kotlin 回归测试覆盖。
- 结束建图后能够进入复核态并保留最后地图，保存与放弃按钮启用，未观察到应用崩溃。
- 点击小地图后可铺满 1920×1017 的 App 可用区域并显示“再次点击地图还原”；全屏期间
  机器人标记持续移动，再次点击后状态面板和建图操作区完整恢复，地图帧从 `#5` 连续推进
  到 `#56`，未重建建图任务或丢失地图状态。
- 验证结束后已停止 App 并恢复 `engineering_mock_enabled=false`。本次结果不证明 NX 主控、
  真实地图流、真实 AppMode 或 RViz 对照链路，仍需按 OpenSpec 任务 5.3 进行联合验收。

- G20 使用图传地址 `192.168.144.144` 同时连接 `33445` 和 `33446`，App 显示底盘与主控
  均已连接、权威控制权为人工控制、NX 已对时；验证期间没有下发非零速度。
- 真实建图期间，App 能持续显示实时栅格、机器狗位置和朝向。NX `/map` 的宽高与 App

  位姿连续。操作者已完成结束建图和保存地图流程验证。
- 断开开发机到 NX 的调试链路以及 G20 的 ADB 后，G20 仍通过独立图传数据面在
  `17:30:45` 启动建图，并在 `17:34:02` 完成原子保存和运行时停止。保存包
  `map-20260818-1733` 包含 `map.pcd`、`map.pgm`、`map.yaml`、`metadata.yaml`、
  `preview.png`、`trajectory.csv`、`calibration.yaml` 和 `index.yaml`；恢复调试链路后
  NX 的 `33446` 仍有来自 RK3588 图传地址的已建立连接。该结果证明遥控建图不依赖
  开发机 SSH 或 ADB 链路。
- 重启 `sar-robot-controller.service` 后没有操作 App 的断开或连接按钮。App 检测超时后
  销毁旧 DEALER transport，约 1 秒内自动建立新会话并恢复人工控制与已对时状态，未再
  出现旧 HELLO 排队造成的 session mismatch 洪泛。
- 客户端已补充回归测试：主控重启时每个新 transport 只有一个在途 HELLO；收到
  `ERROR_CODE_SESSION_MISMATCH` 时立即重建 transport；主动实时地图完整帧能够结清尚未
  完成的最新地图补拉请求，避免地图恢复后再次显示假超时。
- 本轮以 NX 实际 ROS topic 对照 App，没有同时打开 RViz 做画面核对，因此 OpenSpec
  任务 5.3 仍保留未完成；后续只需补 RViz 同屏证据，不重复宣称已经通过的保存流程。
- NX 日志仍出现少量 `timestamp_invalid`、等待时间戳 TF 时丢弃 raycast scan，以及
  bridge 的 CRC32 校验失败。这些异常没有阻断本次地图保存，但属于地图质量与底盘链路
  可观测性问题，后续应单独量化频率和影响，不能因流程成功而忽略。

## 部署与回滚

部署顺序固定为：先处理不兼容旧地图数据，再更新 `legged_driver` 的主控身份权限、bridge
和机器人主控，最后安装同版本 App。回滚时成套恢复同一开发版本的主控与 App，并按目标
版本重新生成地图数据，不承诺新旧地图协议交叉运行；RViz 和原有工程 launch 保持不变。

部署前先在 NX 枚举地图根目录：可确认完整 origin 三元组且两个 YAML 一致的地图可迁移，
无法确认来源或缺少 yaw 的地图直接移出产品目录或重新建图保存。部署后按“代码级 → 工程
Mock → MANUAL/零速度无运动真机 → 安全场地真实运动”逐级验收；任一级失败均停止进入下一
级。回滚必须同时恢复匹配版本的主控、App 和地图数据，不能只回滚其中一端。
