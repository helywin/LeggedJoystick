## 抓取结论

GenisDog 主屏是 Flutter 自绘界面，不能像原生 Android 那样拿到完整 ViewGroup 层级和约束关系。当前能稳定抓到以下信息：

## 画布基准

| 基准 | 尺寸 |
| --- | --- |
| 截图画布 | 1920 x 1200 |
| UIAutomator 内容根节点 | 1920 x 1078 |

后续 Compose 实现建议按横屏全屏 `Box` 叠层做响应式布局。坐标可按 1920 宽度等比换算，高度优先使用底部/顶部锚定，不要写死绝对高度。

## 层级结构

主屏可以拆成 6 层：

| 层 | 内容 | 实现建议 |
| --- | --- | --- |
| 1 | 全屏视频背景 | `media` 层填满屏幕，裁剪填充 |
| 2 | 左上角小视频预览 | 固定左上偏移，白色描边圆角窗口 |
| 3 | 顶部状态与模式栏 | 顶部居中模式按钮，右上网络/工具按钮 |
| 4 | 左侧速度区 | 左中速度等级按钮，点击后显示三挡垂直速度选择 |
| 5 | 右侧工具列 | 灯光/姿态/拍照等纵向悬浮按钮 |
| 6 | 底部动作条 | 第一个按钮控制动作组展开/收缩，展开后显示横向动作按钮列表 |

## Compose 布局建议

| 组件 | Compose 布局方式 |
| --- | --- |
| 根布局 | 全屏 `Box`，强制横屏或横屏优先 |
| 视频背景 | `matchParentSize`，内部使用裁剪填充 |
| 悬浮按钮 | 固定尺寸，使用 `align` 加 `offset` |
| 顶部中间模式按钮 | `align(TopCenter)`，顶部偏移约 48 到 56dp 视觉等比 |
| 左上预览 | `align(TopStart)`，左 40/1920，顶 135/1200 比例换算 |
| 左侧速度区 | `align(Start)`，用垂直 Column 放速度等级和表盘 |
| 右侧工具列 | `align(CenterEnd)`，右边距约 69/1920，按钮间距约 20 |
| 底部动作条 | `align(BottomCenter)`，底部保留 32 到 40dp 安全距离 |
| 动作按钮 | 横向 Row，固定单元宽，选中态使用青色底 |

注意：底部动作条的 XML bounds 只覆盖可访问按钮，截图中的半透明背景比 XML 范围更大。实现时应按视觉容器来做，不要只按 XML 的 `[521,967][1569,1078]`。

### 我们 App 的实现建议

| 项 | 建议 |
| --- | --- |
| 状态模型 | 使用 `SpeedLevel` 保存当前挡位，使用 `showSpeedSelector` 控制轨道显隐 |
| 控件实现 | Compose 中使用自定义三段垂直选择器，不需要依赖 Android 原生 `SeekBar` |
| 点击行为 | 点击大速度按钮显示轨道；点击轨道三段位置更新挡位并保持轨道显示 |
| 协议映射 | 发送 `COMMAND_CODE_SET_SPEED_LEVEL`，payload 使用 `SpeedLevel.SPEED_LEVEL_LOW`、`MEDIUM`、`HIGH` |
| 移动控制 | MOVE 指令仍发送摇杆归一化值；速度挡位由机器人端或控制层按当前 `SpeedLevel` 限速 |

注意：UIAutomator 中的 `0.0`、`1.0`、`2.0` 是 Flutter 语义层暴露值，不建议直接当协议枚举值使用。我们应使用 `legged_driver` 的 `SpeedLevel` 枚举。

## 底部动作组展开/收缩

| 状态 | 开关按钮 Bounds | 动作按钮组 Bounds | 动作节点 |
| --- | --- | --- | --- |
| 展开 | `[391,1005][481,1078]` | `[521,967][1569,1078]` | 站立、匍匐、卧倒、过挡鼠板、扭一扭、爬高墙、过窄墙、锁定 |

| 项 | 建议 |
| --- | --- |
| 状态模型 | 使用 `actionsExpanded` 本地 UI 状态 |
| 协议行为 | 点击开关不发送机器人指令，只改变本地 UI |
| 展开态 | 显示开关按钮和动作按钮 Row |
| 收缩态 | 只显示居中开关按钮 |

### 模式内容

| 模式 | 描述 | 我们 App 的处理 |
| --- | --- | --- |
| 原地模式 | 保持在原地不动，仅保持部分特技动作 | 可映射为 `SPORT_MODE_IN_PLACE` |
| 运动模式 | 手动精准控制移动、转向及基础动作 | 默认手动模式，可映射为 `SPORT_MODE_GENERAL` |
| 巡航模式 | 建图后启用定点巡航 | 第一阶段不做，保留禁用卡或隐藏 |
| 登阶模式 | 自主规划步态跨越多级楼梯 | 可映射为 `SPORT_MODE_STAIR` |

### 我们 App 的实现建议

在 Compose 中把它做成主屏内的 overlay，而不是独立页面：

| 组件 | 建议 |
| --- | --- |
| 展开状态 | `showModeSelector` 控制 |
| 遮罩 | 全屏半透明深灰，顶部按钮仍可见但除关闭/卡片外不响应 |
| 面板 | `Box(align = BottomCenter)`，高度约屏幕 75%，顶部圆角 |
| 标题 | `align(TopCenter)` |
| 关闭 | `align(TopEnd)`，点击关闭 overlay |
| 卡片列表 | `LazyRow`，卡片固定宽度，首尾允许被裁切 |
| 选中态 | 当前 sport mode 卡片加青色描边 |
| 点击行为 | 点击卡片后发送运动模式命令，成功或乐观更新后关闭 overlay |

注意：巡航模式依赖建图/导航能力，不属于当前手动遥控闭环。第一版可以保留视觉但禁用，或不显示该卡，避免用户误以为已经支持自动巡航。

### 我们 App 的实现建议

这个 overlay 很适合承载 `RobotStateMessage`。第一版可以保留视觉结构，但把数据替换为 `legged_driver` 的真实状态。

| 原 App 元素 | 我们 App 映射 |
| --- | --- |
| 两块电池百分比 | `RobotStateMessage.battery.power1` / `power2` |
| 电池颜色 | 根据电量阈值动态切换：绿色、黄色、橙色、红色 |
| 机器狗侧视图 | 继续使用 `icon_dog_status.png` 作为临时素材 |
| 绿色状态标记 | 可作为补光灯、控制权、故障点或连接状态标记 |
| 点击空白关闭 | 保留；也可增加右上角关闭按钮，提升可发现性 |

状态面板第一版建议显示：

| 信息 | 来源 |
| --- | --- |
| 双电池电量 | `battery.power1`、`battery.power2` |
| 充放电状态 | `power_supply_status1`、`power_supply_status2` |
| 当前速度等级 | `speed_level` |
| 当前运动状态 | `motion_status` |
| 当前运动模式 | `sport_mode` |
| 控制来源 | `control_source` |
| 故障入口 | `FaultListMessage` |

实现上建议使用 Compose 绘制电池图标，而不是直接使用截图裁剪。截图裁剪只用于还原视觉比例；真正 UI 应根据实时电量绘制填充高度和颜色。

## 我们 App 的取舍

保留：

| 保留项 | 原因 |
| --- | --- |
| 全屏视频背景 | 遥控场景核心信息 |
| 左上预览窗 | 可用于第二路视频、地图、状态小窗 |
| 顶部居中模式切换 | 当前运动模式需要高可见性 |
| 左侧速度等级和速度表盘 | 手动控制时高频关注 |
| 右侧工具列 | 灯光、拍照、急停等即时工具 |
| 底部动作条 | 常用动作命令集中入口 |

调整：

| 调整项 | 新方案 |
| --- | --- |
| 厂商按钮 | 替换为接管、释放、急停、灯光、设置等我们自己的命令 |
| 充电桩/厂商配网 | 不做 |
| 原遥控器硬件入口 | 不做 |
| 未知图标按钮 | 根据 `legged_driver` 命令重新定义 |
| 小视频窗 | 第一阶段可做占位或第二视频流，后续按视频源接入 |

## 实现优先级

1. 先按截图复刻静态主屏：背景、小窗、顶部栏、左侧速度、右侧工具、底部动作条。
2. 接入底部动作按钮和速度等级，不接视频也能调通协议。
3. 接入左右触屏虚拟摇杆，摇杆常态隐藏，触摸时显示在左右操作区。
4. 接入视频背景和小窗。
5. 做不同屏幕比例适配，重点验证 16:10 和 16:9 横屏。
