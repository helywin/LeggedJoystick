## Context

见 [proposal.md](proposal.md) 的 Why。App 已有独立的 `RobotControllerClient`、权威主控快照、实时建图栅格与坐标转换，但尚未处理地图列表、PNG 预览、定位状态和路径预览。主控协议已经定义相关请求，当前 `MapInfo` 只缺少地图 origin yaw；现有保存器又把该值固定写成零，需要先把坐标元信息链补完整。

## Goals / Non-Goals

**Goals:**

- 让协议解析、地图预览组装、坐标双向转换和状态失效策略保持纯逻辑可测。
- 让 UI 只表达主控权威状态和本地尚未提交的草稿，不用本地乐观状态伪造定位或导航成功。
- 让选点、规划和导航在会话、地图 revision、定位代次和任务 ID 上严格关联。
- 控制内存、磁盘缓存和 ZMQ 队列上限，避免地图预览阻塞命令与安全消息。

**Non-Goals:**

- 不把 Nav2、ROS topic/action 或 TF 暴露给 Android。
- 不在 App 内做路径规划、可通行性判断或目标自动修正。
- 不复用实时建图栅格作为已保存地图真源，不支持多目标路线。

## Decisions

### 1. 先补齐唯一地图格式的 origin yaw

在主控真源 `MapInfo` 增加 `origin_yaw_rad = 12`。地图保存器从 OccupancyGrid origin 四元数提取有限 yaw，同时写入 `map.yaml` 和 `metadata.yaml`；地图仓库要求两个文件都提供一致的有限三元组，再由主控返回。Android 协议副本同步字段并增加编号契约测试。

备选方案是 Android 永久假定 yaw 为零。虽然当前保存地图通常为零，但该假设会在旋转 origin 的合法地图上静默发送错误坐标，因此不采用。当前地图协议与数据仍在开发中，新格式是唯一规范：主控拒绝缺少第三个 origin 分量的旧包，App 缺少完整元信息时禁用选点；部署前直接迁移、清理或重新生成旧开发数据，不保留双解析或默认值分支。

### 2. 地图预览只串行获取选中项并使用有界哈希缓存

地图列表先显示文本元信息和当前标记，只有选中地图才请求预览，避免进入页面就并发拉取全部 PNG。新增纯 Kotlin `MapPreviewAssembler`，同一时刻只组装一个 `map_id + revision + request_id`，限制分片数、总字节数和超时，完整后校验 SHA-256。

合法 PNG 写入 App 私有缓存目录，以预览哈希命名并使用临时文件原子替换；缓存设置总字节上限并按最近使用淘汰。解码失败不会污染缓存。内存只保留当前显示位图和原始合法字节，不让 Compose 状态保存多个大图。

主控重连或 App 重启时，权威快照可能先恢复当前地图，随后地图列表才补齐可显示元信息。列表归约若因此自动选中当前地图，控制器必须像人工选图一样自动从哈希缓存读取预览；缓存未命中时只发送一次有界预览请求。失败后显示明确原因并保留人工重试，不得永久停在“正在获取”状态，也不得借恢复预览触发切图、模式或运动命令。

### 3. 主控客户端扩展请求类型但保持单线程 socket

`RobotControllerClient` 增加地图列表、地图预览、切图、初始位姿、规划、开始导航、取消和停止运行时接口。所有 socket 读写仍只在现有 I/O 线程发生；业务线程只把不可变消息放入有界队列。

待响应表增加地图列表、预览和路径规划类型。地图列表与预览响应必须同时匹配 generation、session 和 request ID；`PathPreview` 再匹配已接受的 preview task ID 和地图 identity。命令继续优先入队，列表刷新和同一预览请求可以合并，绝不让 PNG 分片挤出命令响应。

### 4. 导航状态使用独立 reducer 管理权威事实与本地草稿

新增 `MapNavigationState`，分开保存：权威地图列表/当前地图/定位状态/活动任务/机器人位姿，以及本地地图选择、初始位姿草稿、目标草稿、规划路径和提交状态。主控在定位进入 `TRACKING` 前不会提交新的 `current_map`，因此 reducer 还要单独保存活动 `LOAD_MAP` 任务携带的待初始化地图 identity；等待初始位姿时优先使用它，跟踪后再无缝切换到 `current_map`。停止运行时后主控会保留上次的 `current_map` 作为历史权威信息，App 的加载门禁只依赖选中地图和主控 `ACTION_CODE_SWITCH_MAP` 授权，不因选中地图等于该历史值而禁用重新加载。纯 reducer 根据新快照、命令响应、任务事件、路径事件和连接代次执行失效规则。

会话变化清除全部待提交草稿和路径；地图 identity 变化清除坐标相关状态；定位从等待状态进入跟踪时清除已提交的初始位姿草稿；定位运行时停止并返回待机时清除初始位姿、目标、路径和对应交互提示但保留当前地图；运行时仍活动但定位不再跟踪时只清除目标和路径；取消导航清除自动导航路线但保留当前地图、定位和目标草稿。重连只从完整快照重建权威事实，不保存或重发运动意图。

相比把这些字段直接散落在 Compose 中，reducer 更容易覆盖乱序事件、旧路径和 revision 变化，也避免界面重组触发协议副作用。

### 5. 选点采用按下定位、拖动定向的显式编辑模式

定位工作区复用现有地图画布与 `ContentScale.Fit` 变换，增加地图到屏幕和屏幕到地图的互逆函数，并把 letterbox 偏移纳入换算。普通横屏把地图作为主视觉，地图列表与权威状态压缩为窄栏，不允许两个辅助面板占据大部分宽度。操作者选择“设置初始位姿”或“选择导航目标”后自动进入全屏地图，在地图内按下确定位置、拖动确定朝向；手势处理必须在按下瞬间保存原始坐标，不能把越过触摸拖动阈值后的坐标误作位置。拖动期间实时显示位置、角度和临时朝向箭头，松开后保留数值与箭头，再还原工作区通过独立确认按钮发送。

单击地图默认不直接发送命令；落在地图外边距、占用像素或非有限坐标的操作被拒绝。初始位姿允许落在地图内的未知像素，因为机器人占地和激光盲区可能使轨迹真值附近没有自由栅格；导航目标仍拒绝未知像素。初始位姿只在等待状态可用，目标只在定位跟踪时可用。全屏编辑只改变 Compose 展示状态，不发送命令；松开生成草稿后仍需退出全屏并独立确认。这样比“点一下立即导航”更适合触摸屏，也降低误触造成运动任务的风险。

### 6. 规划预览是开始导航的必要本地凭证

本地为每次目标编辑生成递增 selection generation。请求规划时记录 generation、地图 identity、目标 Pose2D 和返回 task ID；只有同 task ID、同地图且 generation 未变化的 `PathPreview` 才进入可确认状态。目标任何变化都会立即撤销旧路径和“开始导航”能力。

开始导航仍由主控 `allowed_actions` 最终门禁，并重新携带当前地图 revision 和目标姿态；本地预览不是安全授权，只是防止操作者在没有看过路径时误启动。正式任务开始后，UI 使用主控 active task、控制权和任务事件，不再把 preview task 当作导航任务。

### 7. 导航工作区与既有建图、视频和手动输入并存

主屏根据 operation mode 选择建图工作区或定位导航工作区；待机可进入地图管理页。导航自动控制时不发送摇杆连续运动意图，任务动作只保留“取消导航”；取消完成并恢复 MANUAL 后，既有手动输入链路自然恢复，不再通过独立人工接管任务切换。进入维护模式时两类产品工作区都只读。

RViz/launch 工程入口不由 Android 启动或替换，仍按 NX 运行租约切换。App 只显示维护状态并禁用产品命令。

### 8. 正式导航路线与规划预览分开归约

`PathPreview` 继续作为“操作者已经看过本目标规划”的本地启动凭证；`NavigationPath` 只表达正式导航期间 Nav2 最新全局规划。`MapNavigationState` 分别保存两者，正式路线包含 task ID、地图 identity、路径序号、点集和长度。客户端先做 Protobuf 基本解析，reducer 再按会话代次、权威活动任务、地图和严格递增序号决定是否接受，避免 I/O 线程推断 UI 生命周期。

导航权威任务出现时清除旧正式路线并等待新事件；同任务重规划只覆盖正式路线，不修改目标草稿或预览凭证。任务成功、失败、取消、切图、停止定位和会话变化都会清空正式路线。新会话若快照仍存在真实导航任务，可以接收主控随后补发的当前路线，但不会构造或重发任何运动命令。Compose 在同一地图变换下以区别于预览的高对比色绘制正式路线，并在状态窄栏显示“实时路线”的长度、点数和序号。

### 9. 导航界面按任务阶段显示动作，低频信息使用对话框

普通导航工作区取消常驻地图列表和完整权威状态栏，只保留占据主体的地图、当前地图名称、连接/定位/控制权摘要和当前阶段可执行动作。地图列表、版本信息、刷新、加载和停止定位统一进入地图管理对话框；完整运行模式、健康、位姿、活动任务、路线统计和阻断原因进入状态详情对话框。空地图时提供明确的地图选择入口，不再用两个辅助栏长期占用地图宽度。

底部动作栏使用唯一的当前步骤解析规则根据权威状态渐进显示：待机且已选择合法地图时直接提供加载地图；等待初始位姿时只提供设置、重选和确认；定位跟踪时按“设置目标、规划路线、开始导航”逐步推进；正式导航时只保留取消导航。加载地图、发送初始位姿、停止定位运行时和开始导航在执行前通过对话框显示地图版本、位姿或路径摘要；取消导航属于安全收口动作，保持无需二次确认的一键执行。动作栏和状态详情必须复用同一解析结果，避免一个界面显示可执行而另一个界面宣称无步骤。

状态详情分开表达系统健康和当前步骤门禁：全局区域只显示主控快照本身的真实健康阻断；动作区域只读取当前步骤对应的单个 `AllowedAction`。其他动作因业务阶段不匹配产生的 `mapping_not_running`、`not_in_maintenance` 等原因属于正常不可用条件，不得汇总成当前故障。待机且定位运行时未启动时，页头使用中性的“未启动”，仅在主控报告异常或连接状态未知时显示警告语义。稳定原因码转换为面向操作者的中文说明，必要时保留码值用于诊断。

全屏位姿编辑使用本地临时草稿，拖动松开后由“使用此位姿”明确提交到工作区；取消编辑不得覆盖进入编辑前的既有草稿。地图视图使用独立纯逻辑变换保存缩放与平移，围绕双指中心在有界倍率内更新，并在触摸选点前执行逆变换；因此缩放后的地图像素、世界坐标和拖动朝向仍使用同一坐标链。普通浏览允许单指平移，编辑模式保留单指位姿拖动并在出现第二触点时切换为视图变换。地图画布及其路线、位姿等叠加层统一裁剪在当前地图视口内，非全屏圆角工作区不得绘制到页头、动作栏或外部留白。切换地图时复位视图，地图右上角始终提供还原按钮。

主页将建图与定位导航合并为单一任务入口，六种姿态动作则作为需要快速触达的基础控制全部常驻底部展开区域，不设置“更多动作”入口。任务入口的合并负责控制主页横向规模，不以增加姿态操作层级为代价。

### 10. 产品界面使用固定深色语义主题

遥控器工作区以暗色视频和地图为视觉背景，Compose 根主题必须固定使用项目深色 `ColorScheme`，不得跟随 Android 系统浅色模式，也不得启用设备动态取色。原生 Activity 窗口、状态栏和导航栏同步使用深色背景与浅色图标，避免进入 Compose 前后出现浅色闪屏或系统栏断层。

颜色按用途集中定义：背景、基础表面、浮层表面、分隔线、主文字、次文字、强调色、警告色和故障色。页面业务代码优先使用 `MaterialTheme.colorScheme` 和统一语义组件，不再依赖模板紫色、系统默认色或为同一含义重复硬编码近似颜色。深色背景上的正文和按钮文字必须保持可读对比，禁用态通过降低强调度表达，但仍需可辨认。

所有产品对话框复用统一深色对话框容器、圆角、描边、内边距、标题和按钮顺序；对话框标题、说明、列表项和危险动作分别使用统一排版层级。设置页、连接提示、建图命名、地图管理、状态详情和导航确认即使使用不同内容，也必须从同一主题获取表面与文字颜色。类型系统统一标题、正文、辅助说明和按钮标签的字号、字重与行高，业务页面只在地图标注等特殊场景覆盖字号。

状态详情对话框的内容区域保持固定最大高度，权威状态、路线统计、系统真实阻断和当前步骤阻断置于同一纵向滚动容器。阻断项数量或单项文本增长时不得裁掉底部内容，关闭按钮保持在滚动区域外稳定可见；每次重新打开对话框从权威状态顶部开始，不恢复到上一次仅显示阻断列表的滚动位置。

定位摘要优先使用权威运行模式表达正常工作流：待机显示“未启动”，加载阶段显示“地图加载中”，等待初始位姿显示“待初始位姿”，跟踪和丢失分别显示对应结果。即使细分 `localization_state` 在初始化位姿前仍为 UNKNOWN，也不得把已知的权威阶段呈现为未知故障。

## Risks / Trade-offs

- [新增跨仓协议字段造成副本漂移] → 先改主控真源和契约测试，再同步 Android；两个仓库以相同字段号和唯一完整格式构建，部署前清理不兼容旧数据。
- [旧开发地图缺少 yaw 后无法进入列表] → 部署前枚举旧包，需要保留的重新保存或明确迁移，其余清理；不为临时开发数据增加永久兼容代码。
- [PNG 或路径消息过大导致 UI 卡顿] → 有界组装、后台校验/解码、单选预览和最新值覆盖；Compose 只接收完整不可变结果。
- [触摸坐标受缩放和留白影响] → 使用共享 viewport 变换并覆盖横竖尺寸、非零 origin yaw、边界和往返误差测试。
- [路径事件晚于目标修改到达] → selection generation、task ID 和地图 identity 三重匹配，过期结果只记诊断。
- [主控断连时真实导航仍可能处于未知状态] → App 不自动续传目标，立即停止本地自动意图并保留人工 MANUAL 安全降级；恢复后只认新快照。
- [真机地图流程通过但定位或运动尚未验证] → 分阶段验收：先 MANUAL/零速度完成列表、切图、初始位姿和规划，再在安全场地单独批准真实导航运动。
- [路线更新频率高导致旧路径排队或界面重绘过载] → 主控先限频与有界抽样，客户端和 reducer 只接收严格递增序号，Compose 始终只持有最新不可变路线。
- [把操作收进对话框后难以发现] → 主页保留带文字的任务入口且六种姿态动作全部直接显示，导航页空状态直接提供地图选择；安全动作和当前任务主动作始终保持一级可见，只有低频地图管理、完整诊断和运行时操作进入具名对话框。
- [地图缩放后选点坐标偏移] → 缩放、平移、绘制和触摸逆变换共用纯逻辑模型，覆盖锚点保持、往返误差、倍率边界与还原测试。
- [系统主题或动态色破坏操作界面对比度] → 产品根主题固定深色并关闭动态取色，原生窗口同步深色；对颜色对比和对话框语义令牌增加纯逻辑测试，并通过 G20 工程 Mock 截图检查主页、设置、建图和导航弹窗。
- [把其他动作的不适用条件误报为当前故障] → 当前步骤由单一纯逻辑解析器产生，动作栏和状态详情复用；详情只读取当前步骤的 `AllowedAction` 与主控快照全局阻断，并覆盖待机选图回归测试。

## Migration Plan

1. 在 NX 仓库增加 origin yaw 并通过协议、地图仓库、保存器和主控测试；枚举旧开发地图包，需要保留的迁移或重新保存，其余清理后再部署新服务端。
2. 在 Android 同步协议，完成预览组装、坐标转换、客户端和 reducer 单元测试。
3. 实现地图管理和定位工作区，在 Mock 与 G20 上验证布局、误触边界和断连失效。
4. 保持机器狗 MANUAL 与零速度，真机验证地图列表、预览、切图、初始位姿、定位跟踪和规划预览。
5. 在明确安全场地与人员监护下单独验证开始导航、取消、取消后再次规划和再次导航。

回滚前先停止定位导航、确认 MANUAL 和零速度，再成套恢复同一开发版本的 NX 与 App；不承诺新旧地图协议交叉运行。新增字段编号不得复用，地图数据按目标版本重新生成。
