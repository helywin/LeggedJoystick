# Design

## Context

设置持久化控制 IP 与头尾 RTSP URL，`Controller` 发起连接时使用设置值。遥控输入层虽能识别 UniRC 与 G20，用户确认通信入口应由本地 IP 决定。已知底盘网段为思翼图传 `192.168.168.0/24`、另一图传 `192.168.144.0/24`、热点 `192.168.234.0/24`。

## Goals / Non-Goals

**Goals:**

- 根据活动网卡 IPv4 选择标准控制和 RTSP 入口，不依赖遥控器型号。
- 连接前刷新入口，保留非标准手工地址与现有零速度保护。

**Non-Goals:**

- 不配置网卡、路由或图传电台。
- 不在已接管运动期间自动切换另一连接。

## Decisions

### 1. 读取活动网卡而非默认网络

系统网卡枚举读取已启用、非回环接口的 IPv4 地址。图传网可能不提供互联网，也可能不是 Android 默认网络；只读默认网络会漏检。仅匹配三个明确的 `/24` 网段，优先级为 `168`、`144`、`234`。

### 2. 标准入口随网段重算

设置字段不变。加载设置及连接前，识别到已知网段时将三个标准底盘 IP 和对应标准 RTSP `/front`、`/back` 映射到选中入口；非标准地址、端口和路径不覆盖。无匹配网段时保留设置原值。连接前只更新内存设置，不覆盖用户保存的手工值。

### 3. 切换链路仍遵守断连保护

当前连接失效沿用现有断连与零速度保护。下一次发起连接时重新读取本地 IP，不在运动中静默切换底盘端点。

## Risks / Trade-offs

- [网卡已有地址但图传链路未通] → 连接仍可能失败；以端口及 RTSP 真机验证区分地址选择和实际连通性。
- [同时存在两个图传网段] → 使用固定优先级，现场若出现该拓扑再核对路由。
- [标准地址被当作手工覆盖] → 标准地址随网段重算，固定入口应使用非标准手工地址。

## Migration Plan

1. 加入网卡 IPv4 读取与纯逻辑映射测试。
2. 在加载设置和连接前应用映射，验证两个 flavor 的构建和核心测试。
3. 签名并安装巡检版到思翼遥控器，读取活动网络和 App 日志；不发送运动命令。
